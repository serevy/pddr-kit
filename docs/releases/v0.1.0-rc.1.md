# PDDR Kit v0.1.0-rc.1

`v0.1.0-rc.1`は、PDDR Kitの最初のリリース候補です。PDDRを記録するだけでなく、AIが記録を過剰なルールとして扱わないためのConsumption Contractと、安全な導入・更新経路を含みます。

## 含まれるもの

- PDDR v0.1の仕様とMarkdownテンプレート
- 判断状態と提供状態を分離したライフサイクル
- `unknown`と`needs-confirmation`を使った不確実性の保持
- `pddr-recorder` Skill
- 非破壊な`init`、記録の`validate`、差分確認付きの`upgrade`
- 管理ファイルのハッシュを保持する導入先マニフェスト
- PDDR Kit自身の7件のPDDRとGitHub Actionsによる継続検証
- 記録作成・更新11ケースと、安全解釈4ケースの評価資料・生出力・判定結果

## 検証済みの範囲

- PDDR Kit自身でのdogfoodingとCI
- 既存の別プロジェクト（Audio Guardian）への初回導入、安全な更新、PDDR CI、既存のWindows CI
- GPT-5.6 Sol / mediumによる記録作成・更新: 11/11
- GPT-5.6 Luna / mediumによる記録作成・更新: 10/11
- GPT-5.6 Sol / mediumとLuna / mediumによるConsumption Contract: それぞれ4/4

## 既知の制約

- リリース候補であり、stable版までに仕様や管理ファイル形式が変わる可能性があります。
- Lunaの記録作成・更新評価では、状態判定は正しかったものの、1ケースで既知の選択肢が下書きから欠落しました。完全性は人または上位モデルによる確認が必要です。
- マニフェスト導入前の既存環境で`--bootstrap-manifest`を使う場合は、現在の管理対象ファイルが正しい基準であることを人が先に確認する必要があります。
- 新規プロジェクトへの導入と、Audio Guardian以外の異なるプロジェクトでの運用検証は未完了です。これらはstable版の判断材料にします。
- Jevなどの有償・外部サービスは任意拡張であり、本リリースの依存関係には含まれません。

## 導入前の注意

PDDRはPolicyではなく、判断の文脈とEvidenceです。現在のユーザー指示、プロジェクト方針、組織Policyを優先し、記録の新しさ・反復・表現の強さだけから権限を推測しないでください。導入・更新方法は[`docs/adoption.md`](../adoption.md)を参照してください。
