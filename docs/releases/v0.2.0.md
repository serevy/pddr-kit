# PDDR Kit v0.2.0

`v0.2.0`は、v0.1.0のportableなmanaged coreを維持しながら、重要判断の取りこぼしを節目で再点検する運用と、そのcheckpoint自体の実行漏れを補完する仕組みを追加したminor releaseです。

## 主な更新

- **Milestone audit**
  - major experiment / release / delivery phase boundary
  - Issue / roadmap audit
  - 複数Evidence-bearing Issue / PRのclose・consolidation
  - checkpointはPDDR作成quotaではなく、durable decisionがなければno-opを正常結果とする
- **Optional checkpoint CI**
  - `AGENTS.md`、roadmap、architecture等のhigh-signal changeをdeterministicに検出
  - Check / Job Summaryへexecution traceを残す
  - PR本文へ `## PDDR checkpoint` / `Review: pending` markerを追加
  - 後続Agent / maintainerがbounded auditして `Review: completed` へ回収
  - PDDRを自動作成・自動承認しない
- **Product-level versioning contract**
  - release versionはmanaged coreだけでなくSkill / guidance / optional integrationを含むPDDR Kit全体を表す
  - consumer manifestの `kit_version` はmanaged coreを最後に導入・更新したKit source versionのprovenance
  - optional integrationはreleaseのversioning対象だが、managed-core `upgrade`では自動上書きしない
- README多言語構成と導入説明を整理

## 既知の制約

- checkpoint CI v1はGitHub Actions向けのoptional integrationです。GitHub Actionsを使わないconsumerでは従来どおりAgent Skill / project guidanceでmilestone auditを運用します。
- PR本文を書けない場合のcomment fallbackと、fork等でwrite permissionがない場合のSummary-only degradationは実装済みですが、v0.2.0 release前のdogfood範囲には含めていません。
- detectorは誤検知を抑えるためhigh-confidence signalに限定しています。PR数やEvidence量だけからPDDR必要性を推測しません。
- milestone audit用に追加したSkill評価ケースはrepository validation済みですが、Sol / Lunaによる独立forward-testはまだ実施していません。
- remote latest releaseを問い合わせる `pddr upgrade --check` は未実装です。
- optional integrationはconsumerのCI・権限・運用規則を尊重するため、managed-core `upgrade`では自動導入・自動更新しません。

## v0.1.0からの更新方法

新しいPDDR Kit checkoutから、managed coreの差分を先に確認してください。

```bash
python scripts/pddr.py upgrade --target /path/to/your-project --dry-run
python scripts/pddr.py upgrade --target /path/to/your-project
```

`upgrade`が自動更新するのはmanifestで追跡されたmanaged coreだけです。

optional checkpoint CIを利用する場合は、[`docs/adoption.md`](../adoption.md#optional-checkpoint-ci)の手順に従いdetectorとworkflow templateを明示的に導入してください。

## 導入前の注意

PDDRはPolicyではなく、判断の文脈とEvidenceです。checkpoint signalもPDDR作成義務ではありません。現在のユーザー指示、プロジェクト方針、組織Policyを優先し、記録の新しさ・反復・表現の強さだけから権限を推測しないでください。
