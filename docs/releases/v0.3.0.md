# PDDR Kit v0.3.0

v0.3.0はv0.2.1以降の**後方互換なminor release**です。最初の外部利用フィードバックで確認された、AI向け運用規則の配置、Agent Skill更新、記録の承認・訂正、並行PRでの採番の課題へ対応しました。PDDRを日常の作業ログに変えず、**判断の承認権限は厳密に、記録の訂正は柔軟に、AIによる変更は透明に**という境界を保ちます。

## 主な変更

- **AIツール別の導入ガイド**（[#50](https://github.com/serevy/pddr-kit/issues/50)、[PR #55](https://github.com/serevy/pddr-kit/pull/55)）：`AGENTS.md` / `CLAUDE.md`の読み込み条件・ファイルの優先順位・共通PDDRルールの記載例を追加。特定のAIを必須にはしません。
- **明示的なAgent Skill更新**（[#51](https://github.com/serevy/pddr-kit/issues/51)、[PR #58](https://github.com/serevy/pddr-kit/pull/58)）：`upgrade --include-skill`と独立した`.pddr/skill-manifest.json`により、利用者が明示的に登録した`pddr-recorder`をハッシュ検証付きで更新可能に。既定の`upgrade`は従来どおりcoreのみを更新します。
- **承認証拠の再利用・訂正の透明性**（[#52](https://github.com/serevy/pddr-kit/issues/52)、[PR #56](https://github.com/serevy/pddr-kit/pull/56)）：既に確認された人間の意思決定を重複して承認させずに記録し、誤記録の訂正と新しい意思決定を区別。自動マージ・CI成功だけでは承認済みにしません。新しいSkill評価ケース5件を追加。
- **並行PRでのID衝突対策**（[#53](https://github.com/serevy/pddr-kit/issues/53)、[PR #57](https://github.com/serevy/pddr-kit/pull/57)）：Open PRも含めた採番、最新baseでの再検証、衝突時の安全な採番変更を案内。競合シナリオを回帰テストへ追加。
- **利用者向けドキュメント・CI**（[PR #59](https://github.com/serevy/pddr-kit/pull/59)、[PR #60](https://github.com/serevy/pddr-kit/pull/60)）：5言語READMEを更新し、一時consumerに対するCLIの実行テストとREADMEのコマンド整合性テストを追加。
- **CI実行条件の整備**（[Issue #47](https://github.com/serevy/pddr-kit/issues/47)）：既存のread-only検証へのstep追加を優先し、独立したvalidationとoptional checkpointにtimeoutなどを設定。既存の権限分離・検査範囲・required checkを維持。
- **リリース手順の統一**：main上の手動GitHub Actionsからrelease guard検証後にtagとGitHub Releaseを公開する手順を明文化。新しいSkill評価ケースもpublication gateへ追加。

この機能群に関する設計判断は[PDDR-0013](../records/PDDR-0013-transparent-revisable-records.md)と[PDDR-0014](../records/PDDR-0014-optional-skill-upgrades.md)へ記録しています。

## v0.2.1からの更新

PDDR Kitの**v0.3.0 tag/checkout**で、まず既存coreへの変更予定を確認してください。

```bash
python scripts/pddr.py upgrade --target /path/to/your-project --dry-run
python scripts/pddr.py upgrade --target /path/to/your-project
```

記録、設定、独自のAI規則、CIはcore `upgrade`では自動更新されません。既存ファイルに手修正がある場合は競合として停止し、手動レビューが必要です。

Agent Skillを追加で管理したい場合だけ、**初回に配置先を指定して**明示的に登録します（例はClaude CodeのSkill配置先。利用環境に合わせて変更します）。

```bash
python scripts/pddr.py upgrade --target /path/to/your-project --include-skill --skill-path .claude/skills/pddr-recorder/SKILL.md --dry-run
python scripts/pddr.py upgrade --target /path/to/your-project --include-skill --skill-path .claude/skills/pddr-recorder/SKILL.md
```

その後は同じKit側から`--include-skill --dry-run`、`--include-skill`を指定すれば、保存した配置先を使用できます。未追跡の既存Skillが現在のsourceと異なる場合や、登録済みSkillに変更・欠落がある場合は**上書きせず停止**します。古い手動導入版は差分を確認して明示的に移行してください。通常の`upgrade`ではSkillを更新しません。

AIツール別の運用規則は[導入ガイド](../adoption.md)を参考に、各consumerで明示的に適用してください。checkpoint CI等のoptional integrationも引き続き別管理です。

## 既知の制約・非目標

- Skill登録の初回は明示的な配置先指定が必要です。CLIは1つの`pddr-recorder` Skillを対象とし、任意の既存Skillを無条件で自動管理化しません。
- 既存ファイルの競合は**書き込み前**に検出しますが、ディスク障害・停電などの複数ファイルにまたがる完全なトランザクション性は保証しません。
- `AGENTS.md`、`CLAUDE.md`やCIをKitが自動更新するわけではありません。AIへの指示だけで承認権限や安全機構を強制するものでもありません。
- 並行PRの「Open PRの最大番号+1」は原子的な予約ではありません。CIはチェックアウトされたレコードの重複を検出するもので、中央採番サービスはありません。
- 高リスクな実機・Physical AI・安全関連プロジェクトの承認・検証ゲートは、導入先の承認済みPolicyと実機側の独立安全機構で別途定義してください。
