# PDDR Kit v0.2.1

`v0.2.1`は、v0.2.0で追加したoptional checkpoint CIの権限境界を強化するpatch releaseです。新しいconsumer-facing capabilityは追加せず、PR headを観測する処理とPRへ書き込む処理を分離します。

## 変更内容

### Read-only signal workflow

`PDDR checkpoint` workflowは通常の `pull_request` eventでPR headを観測しますが、権限を次に限定します。

- `contents: read`
- `pull-requests: read`

PR headの `.pddr/pddr_checkpoint.py` を実行するjobはPR本文・commentへのwrite permissionを持ちません。

### Trusted marker writer

PR本文へのmarker writeは、signal workflow完了後の `workflow_run` で動く別workflow `PDDR checkpoint marker` へ分離しました。

writerは:

- repositoryのdefault branchをcheckout
- GitHub APIから現在のPR metadata / changed filesを取得
- default branch上のtrusted detectorでsignalを再計算
- recommended signalかつ既存checkpoint headingがない場合だけPR本文へpending markerを追加
- PR本文を書けない場合はcheckpoint commentをfallback
- PR headのcode / artifactをcheckout・実行しない

という境界を持ちます。

`pull_request_target`は使用しません。

## v0.2.0からの更新

managed coreは通常どおり、新しいPDDR Kit checkoutから差分確認後に更新できます。

```bash
python scripts/pddr.py upgrade --target /path/to/your-project --dry-run
python scripts/pddr.py upgrade --target /path/to/your-project
```

checkpoint CIを利用しているconsumer、または新たに導入するconsumerでは、detectorと**2つのworkflow**を明示的に同期してください。

```bash
cp scripts/pddr_checkpoint.py \
  /path/to/your-project/.pddr/pddr_checkpoint.py

cp templates/checkpoint-ci/pddr-checkpoint.yml \
  /path/to/your-project/.github/workflows/pddr-checkpoint.yml

cp templates/checkpoint-ci/pddr-checkpoint-marker.yml \
  /path/to/your-project/.github/workflows/pddr-checkpoint-marker.yml
```

optional integrationはmanaged-core `upgrade`では自動更新されません。

## 既知の制約

- checkpoint CIはGitHub Actions向けのoptional integrationです。
- primary PR-body marker pathはconsumer E2E済みです。
- PR本文write失敗時のcomment fallbackは実装済みですが、このpatch releaseのdogfoodでは独立したfailure injectionまでは行っていません。
- signalはPDDR作成義務を意味しません。通常のPDDR thresholdでbounded auditし、no-opを正常結果として扱います。
